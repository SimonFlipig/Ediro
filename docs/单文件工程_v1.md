# 单文件工程与自动保存

## 使用规则

- 新工作自动建立在程序的 `Project/` 下，使用 `.ediro` 工程文件。界面底部显示实际文件位置。
- “项目记录 → 打开工程…”或拖入一个 `.ediro`，直接编辑该文件。最近记录按文件路径区分，同一个路径重复打开不会派生项目。
- “另存为…”创建独立的新工程，并切换到目标文件继续编辑；保留来源工程。选择已有目标文件时由系统保存窗口确认覆盖，取消则保持原状；选择当前工程自身时执行普通保存，保持工程身份和存储格式。覆盖前完整生成并校验临时工程，再替换目标；准备或替换失败保留已有目标，目标在准备期间发生变化则拒绝覆盖。
- 导入原图立即复制进工程的工作区，并随自动保存收入工程。生成结果、编辑参考、蒙版、缩略图、实际请求、待恢复返回值和历史记录都在工程内。
- 成品通过“导出”写成普通图片，默认位置是 `output/`，生成结果默认命名为 `Ediro_年月日_时分秒_随机后缀.png`（或对应的 jpeg/webp）。旧工程中的结果导出时也采用此规则。导出图片不会因工程继续编辑而改变。
- 导出会在本机登记图片与来源工程、结果版本的对应关系。“恢复旧产出”或拖回工作区可创建新的 `.ediro`，恢复该版本的参数、模块和参考图，保留原工程与历史快照。仅作为素材、拖入参考模块仍只导入图片，不切换工程。恢复不会调用模型。
- 识别同时校验图片内容；图片改名或移动后仍可从本机已登记且可读取的工程找回。修复前导出的图片也可从这些工程补认；同一图片有多个来源时需选择。来源工程未登记或移动过时先重新打开它，再恢复图片。导出的普通图片不包含完整工程，来源工程丢失或图片内容已被修改时不能凭图片重建配方。
- 历史结果选中不要求原本机模型接入仍存在。原接入缺失时按同一具体模型预设匹配可用接入，优先已选渠道或同预设的默认模型；只有一个候选时自动绑定，多个候选且无明确偏好时保留历史参数等待选择。无可用模型仍可查看、导出和修改模块，生成前须完成模型选择。新的配方及任务快照保存预设身份；旧记录仅使用已知映射和准确型号识别，不猜测自定义别名，不改写历史任务。
- 从新工程的结果列表移除版本只隐藏它，保留历史所需像素，不删除已导出的图片。目前不做工程体积压缩整理。
- 旧工程中已经明确删除、且没有被当前/停用模块、历史请求或蒙版输入使用的结果，原图不存在时仍可另存为：保留已删除素材的身份、任务、版本和可用缩略图，不要求找回已删除原图，也不以缩略图冒充原图。仍被引用或并未标记删除的缺失素材继续报错，需要重新定位。
- 旧目录工程与旧产出恢复继续走原有读取流程，不自动批量转存或删除旧文件。打开旧包后可以“另存为…”转换为自包含工程；转换时缺少原图会报错，不宣称收齐。
- 新建与另存为使用去重存储：相同图片字节在一个工程内只保存一份，素材、请求记录及暂存结果可以共用。旧版 `.ediro` 继续按原格式编辑，侧栏提示“另存为可去除重复图片”；另存为创建新版副本并切换，原文件保留。新版副本需要新版 Ediro 打开。
- “项目记录 → 删除”经确认后将对应 `.ediro` 文件移到系统回收站，确认框显示实际路径；导出的图片和其他工程保留。删除当前工程前补存并切换新工作，保存失败或回收站操作失败不当作删除成功。工程文件已不存在时只清理入口。删除成功后清理其已保存的私有缓存与封面，未保存的恢复缓存不做永久清除。从系统回收站还原后可用“打开工程”重新加入记录。
- 旧目录工程删除只移动 `Project/work-*` 这个项目文件夹，外部素材、`input`、`output` 和迁移备份保留；其他旧工程仍引用该文件夹中的素材时阻止删除。已删除记录不在下次启动时从旧工作目录重新迁移。此前仅“移除入口”的记录不会被追溯删除。

## 自动保存

普通提示词、参数、模块、素材和蒙版调整由 Workspace 合并，停顿约 2 秒后写入；蒙版界面还会合并短时间内的笔画提交。输入框不需要先失焦。

请求入队、发送前的任务状态与实际请求、模型返回暂存、结果和版本保存均立即落盘。保存失败不发送新的生成请求，也不自动重试付费请求。

切换项目、新建工作和正常关闭前补存。关闭前桌面桥接先收集尚在输入框或蒙版窗口中的内容。已经保存且没有新修改时，手动保存和关闭不会重复写入工程；关闭需要终止任务时仍立即保存状态。保存失败保留窗口，允许重试或另存为。`Ctrl+S` 可主动立即保存。界面区分等待自动保存、已保存和保存失败。

突然断电或强制结束时，尚在 2 秒合并窗口内且未写盘的最新编辑仍可能丢失；已经提交的事务不会被部分覆盖。

## 格式与读写边界

`.ediro` 使用 SQLite 容器，`application_id=0x45444952`。格式版本与项目 JSON 的语义版本独立。新建与另存为使用 `user_version=2`，仍可读写 `user_version=1` 的旧工程，普通保存不会隐式升级原文件。

v2 的 `document` 表保存容器身份与修订号，`entries` 保存逻辑文件的名称、SHA-256 和还原大小，`blobs` 按 SHA-256 保存唯一字节内容，`parts` 保存有序的内容引用。图片本体、请求内的相同图片和暂存返回共用同一个二进制块；素材身份和任务身份保持独立。只有字节完全一致才合并，不按文件名、视觉相似度或像素近似匹配。

实际请求先按原来的流程捕获，再由 worker 在持久化时把可识别的标准图片 Base64 替换为二进制块引用。文字片段保留原字节，读取时按原顺序拼回，逐条校验完整记录哈希；不会用当前配方或新版适配器重编译历史请求。JSON 的空白、顺序、转义和数字写法，以及 multipart 的同名字段、文件名和图片顺序均保留。不认识的编码原样保存。界面/API 仍读取完整的原始请求记录。

一次事务同时更新条目、分段与二进制块，仅回收没有任何分段引用的块；保留历史记录和已移除结果所引用的图片。SQLite 的空闲页可供后续保存复用，普通保存不承诺立即缩小磁盘文件，另存为其他目标会创建紧凑的新文件。参考图复用不再重复增加图片字节，新生成的不同图片仍会增加工程体积。

条目只允许项目 JSON、`assets/` 图片、`model-inputs/` 请求 JSON、`pending-results/` 暂存返回。条目名称、单条大小、条目数量、总展开大小在打开时校验；首次展开或工程/缓存发生变化时验证内容哈希。单文件工程拒绝外部素材引用。凭据和连接库不进入工程。

后台 worker 执行 SQLite 和大图片读写。使用 DELETE 日志与 FULL 同步，每次保存通过事务更新变化条目；已有图片根据缓存文件签名跳过，不随参数修改重新压缩或重写。正常提交后无需携带 WAL 文件。保存进行中可能短暂存在 SQLite 恢复日志，不应在写入过程中手工复制工程。

打开时恢复到 `.local/runtime/document-cache/` 私有工作缓存，保存位置始终显示工程文件。正常关闭或切换后保留每个文件的一份已保存缓存，再次打开时只有容器身份、修订号、工程文件时间/大小及所有缓存条目的签名均一致才复用，避免重复读取和展开全部图片；否则从工程重新校验展开。缓存通过原子移动独占使用，多个打开实例不共享工作目录。缓存缺失不影响工程完整性；关闭程序后可以清理 `cached-*` 目录，下次打开会重建。缓存不是另一个工程，不需要随 `.ediro` 携带，也不应放入用户素材库。带未保存恢复标记的 `document-*` 目录继续保留。项目封面缓存和最近文件入口也位于运行数据中。

每次写入校验容器身份和修订号。文件被替换或另一处已修改时拒绝覆盖，保留内存/本地内容供另存为。使用中移动文件会导致保存失败，需要重新打开或将当前内容另存为。

未成功提交的本地缓存带恢复标记，下次启动提示“恢复并另存为”，恢复为新工程，不覆盖原文件。已暂存的模型返回在重新打开时可恢复，不自动重新请求。另存为先完成临时文件，再发布目标；旧格式保留，可回到旧程序继续使用旧工程。

## 验证与边界

测试覆盖移动工程、删除原图、重开、参数更新不重写图片、另存身份、重复打开、两个写入者冲突、事务中断回滚、失败缓存发现、暂存返回恢复、合并自动保存、请求前保存失败，以及旧包转换。

Electron 隔离测试覆盖真实桥接、输入框未失焦时关闭、拖入工程、另存为切换、混合拖入拒绝、状态/路径显示和重启恢复。测试使用模拟模型，不消耗付费生成额度。

构建后用 Electron 执行 `scripts/document-desktop-smoke.cjs` 可重跑桌面检查（清除 `ELECTRON_RUN_AS_NODE`）；报告和截图放在 `.local/document-desktop-*`，不使用真实项目。单元/存储测试见 `tests/document.test.ts`，运行需 Node 22.12+。

首版没有 ZIP 导入、系统级文件关联、工程内图片垃圾回收或跨进程实时同步。超大工程仍需实际数据验证；打开时会用额外磁盘空间展开工作缓存。用户的素材管理器是否识别并解析 SQLite 工程，需要在该管理器中实际确认。

去重针对 `.ediro` 内的持久存储。私有缓存仍展开完整图片及请求 JSON，便于现有读取、恢复和兼容打包流程使用；缓存大小不会与去重后工程大小相同。缓存可重建，不需要携带。

存储依据：[SQLite application file format](https://www.sqlite.org/appfileformat.html)。

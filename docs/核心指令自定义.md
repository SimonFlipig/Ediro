# 核心指令自定义

设置中的“核心指令”提供主体、构图、风格、视角的生图指令与独立推理指令，以及通用、陈列师的角色指令。生图指令保留原生图文和文字加图片集合两种表达；模块与角色身份、图片发送范围、推理输出约束继续由程序管理。

## 编辑与预览

- 未自定义的项以灰色只读文字显示出厂默认。启用自定义从当前默认内容开始；显式空字符串表示清空该项文字，取消自定义表示跟随默认。
- 每个模块的两种生图表达独立设置。预览仅构造当前项，用实际编译器展开占位符，模拟图片从 `image_1` 开始；未自定义时可预览该项默认，不引入当前工程的其他模块。空白表达预览为空。视角支持试填角度。
- 切换“生图指令 / 推理指令”可分别设置参考图的生图用途和推理时的识别、整理要求。推理指令与角色只预览各自正文，不混入生图预览，也不调用模型。
- 修改、恢复默认、导入只更新草稿；“保存并应用”后才写入运行配置并即时用于后续任务，无须重启。已有排队或执行中任务继续使用自己的快照，历史任务不重写。
- 修改所用角色或参与的推理指令会让自动提示词建议重新推理，不自动发起请求；仍可使用当前正文生成图片。
- 离开设置或关闭程序时保护未应用草稿；Ctrl+S 保存当前指令设置。

## 预设、恢复与导入导出

模块生图指令、模块推理指令与角色分别管理命名预设，支持另存、更新、重命名和删除。保存预设用于收藏当前文字及默认／自定义状态；“保存并应用”才让当前选择用于后续任务。切换预设前会保护未保存的修改，删除预设后当前文字保留为自定义。

“恢复此项默认”移除当前指令项的覆盖及预设选择，“全部恢复默认”恢复全部生图、推理与角色指令。两者都保留已保存的预设库，保存并应用后生效，不涉及工程、模型、密钥或其他设置。

导出的版本 2 JSON 包含自定义指令、推理指令、预设库和当前选择，可包含尚未应用的编辑。整套配置导入为草稿，查看并保存后替换当前配置与预设库。旧版自定义指令 JSON 仍可导入，保留现有预设库和独立推理指令。未知模块、角色、字段、版本或非法模块占位符均拒绝，当前有效配置保留。用户可手动将导出文件带到另一份 Ediro 使用。

## 运行数据与旧工具兼容

当前设置文件为 `prompt-settings.v2.json`，与其他运行配置同目录：开发版 `.local/runtime`、安装版 `%APPDATA%/Ediro/runtime`、便携版程序旁 `data/.local/runtime`。三个位置分别保存，不互相同步。预设与推理指令保存在程序设置中，不随工程迁移。没有自定义的项跟随应用版本更新，自定义项保留。

没有版本 2 文件时，先兼容读取已有 `prompt-customizations.v1.json`；若该文件也不存在，则从 `prompt-config.v1.json` 中提取与当前发布默认不同的可编辑指令作为用户覆盖。旧文件不改写，之后在设置页保存时写入版本 2 文件。新文件存在后，对这四个模块的可编辑文字以新文件为准，避免恢复默认后旧工具配置重新生效。旧文件的模块名称仍使用；标题、图片标签与分隔符留给旧格式和历史快照，新普通生图使用下述按输入模式区分的边界。后续从旧 PromptTuner 写入旧文件不会覆盖新设置页管理的这些文字。

## 普通生图的 Markdown 与 XML 边界

普通生图的新编译快照使用 `format_version: 4`。编译器保存未转义的模块语义块供预览和追溯，在输入适配阶段按所选模式生成请求文字：

- **保持图文顺序**：使用 `## 1. 模块名称` 这样的 Markdown 标题，每个有效模块都有连续编号，提示词正文和图文模块也有标题。保留原生图文表达、图片、用户补充的原始顺序；每张图片紧跟对应的纯文字 `image_N` 标签。相邻的同模块文字合并为文本块，不跨图片移动文字。正文与自定义名称保持原文，不做 XML 转义。
- **编号拍平**：保留 XML `generation_request`，参考模块以 `module` 分组，编号表达放在 `reference_rules`，用户补充放在 `requirements`，最终正文放在 `generation_prompt`。图片集合独立上传；有图片时，`image_mapping` 明确说明 `image_N` 对应实际附图列表的第 N 张图片（从 1 开始），与模块编号无关。`image_ref` 使用相同编号。正文和自定义名称只在发送时做 XML 转义。已有的自动比例文字要求保留在根节点内。

两种模式共用模块内容、过滤规则和用户排序，保留原有原生／编号自定义指令。标题、标签和边界由程序管理，旧布局模板不参与格式 4 的拼接；设置、卡片和单项预览继续显示原文。重复模块、重复图片与多个提示词按原顺序分别保留，模块编号不代表权重；构图与视角不增加冲突判断或优先级。API 参数不变。

生成前按实际选定模式检查有效文字：图文模式检查原生表达，拍平模式检查编号表达，两者都包含本次用户正文或补充。Markdown 标题、图片标签和 XML 外壳不计为有效指令。明确清空某种表达不会恢复默认，也不会阻止另一种有效表达使用。

理解／推理与核心指令单项预览继续使用既有编译规则。蒙版编辑保持专门的底图、区域图或 mask 字段约定。格式 3 的原生 XML、格式 2 和无版本快照仍可读取；历史重试使用冻结的 `adapted_input`，不会套用新模板重编。恢复历史配方后重新生成，则使用当前格式 4。

## 验证

核心与存储测试包括 `tests/prompt-customization.test.ts`、`tests/prompt-customization-repository.test.ts`、`tests/prompt-settings.test.ts` 和 `tests/prompt-settings-commands.test.ts`。构建后可运行 `scripts/prompt-settings-desktop-smoke.cjs`，使用独立运行目录、真实 Electron 页面与 controller、模拟推理和禁止外网，检查默认正文、预设、保存、恢复、导入导出、角色与推理指令生效、重启及不同窗口尺寸。测试不证明真实模型效果。
